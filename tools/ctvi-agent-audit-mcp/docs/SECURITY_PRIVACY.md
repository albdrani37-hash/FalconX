# Security and privacy engineering notes

CTVI Agent Audit MCP 0.3.0 is a separately versioned prototype around the unchanged utility engine 0.2.0. It is not a security certification or scientific validation.

Unlike the standalone local CLI, a remote MCP invocation sends the supplied trace text to the server operator and returns a structured report to the calling client. Users should minimize and redact data before transmission. Do not send credentials, authentication codes, government identifiers, payment-card information or protected health records. This server does not detect or redact every sensitive value.

The handlers use only the supplied trace string and fixed code/catalog data. Artifact root access is not exposed; artifact declarations remain unchecked at the byte level. Paths and URLs in a record are data. The audit does not fetch URLs, open those paths, execute tools, invoke a model API or access client filesystem roots. Optional text may be parsed but is omitted from reports. Structured fields, counts, outcomes and fingerprints can still be sensitive.

Request size is bounded before SDK parsing, including chunked request bodies. Duplicate JSON keys, malformed input, nesting/type errors and oversized trace/evidence/event counts are rejected. The adapter validates published input and output JSON schemas. Application errors use fixed codes; protocol errors are sanitized. Tool metadata explicitly declares readOnlyHint true, destructiveHint false, openWorldHint false and idempotentHint true. These declarations describe behavior and do not replace access control.

The provided entry point disables runtime application/dependency logs and HTTP access logs to avoid accidental payload logging. No telemetry exporter or telemetry environment configuration is installed. The MCP dependency includes the OpenTelemetry API; that is a dependency, not a claim that it was removed or a guarantee about an operator's environment. Application code creates no trace/report database or output file. It retains processing data in memory for the request. No memory zeroization guarantee is made. Package installation, Python caches, OS swap/crash dumps, client transcripts, network intermediaries, host monitoring and backups remain outside this promise. The Docker recipe sets PYTHONDONTWRITEBYTECODE, and test commands use -B.

A hosted deployment needs a new operator-specific privacy notice accurately describing its actual data flow, purpose, infrastructure and retention. Existing offline 0.2.0 policy must not be reused as if the remote service never receives data. Support: albdrani36@gmail.com; use minimal synthetic reproductions, not private traces. Voluntary email remains subject to the mailbox provider and manual handling; no automatic retention/deletion service or guaranteed response time exists.

Controls were tested against synthetic cases and independent engineering probes. They do not detect fabricated complete logs, prove provenance authenticity, replay stochastic agents, validate proposed CTVI constructs, measure real-world accuracy or demonstrate production readiness. See the evidence reports for exact test scope and remaining deployment gates.

The application enforces a global per-process token bucket of 60 MCP POST requests per minute, burst 10, returning fixed HTTP 429 when empty. It is not a per-user or distributed limit. Health/domain-proof GET routes are excluded from that bucket and still need upstream protection. `/healthz` returns fixed `ok`. The exact `/.well-known/openai-apps-challenge` path returns only a configured `CTVI_OPENAI_APPS_CHALLENGE` public token (1–256 restricted ASCII characters); it is 404 when unset. The token is not authentication and no domain verification is claimed until the platform confirms it. No directory/file reading is used. Captured SDK response bodies are bounded to 1,100,000 bytes and 64 messages before concatenation.
